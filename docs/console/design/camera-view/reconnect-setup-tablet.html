Coming back, the Setup deck, and a tablet

1 · Does it restart when data returns?

Yes — and the useful answer is which parts, because they are not the same parts. The aircraft never stopped: capture, encode and the ground‑station push ran throughout. What died was the browser's session, and re‑establishing it is resuming an instruction you never withdrew, not making a new one.

Three things happen and each is deliberate. The page reconnects on its own, with backoff, and counts the attempts — it does not wait for you to press anything, because you already asked for a live picture and never took the request back. It asks for a keyframe on subscribe rather than waiting for the next natural one, which is R‑VID‑09 and the difference between a picture in 0.2 s and a grey rectangle for however long the GOP is. And it re‑reads every setting from the aircraft before showing it as current, because the board may have rebooted while you were away — K‑41 says yours does — and a page that redrew its remembered values would show a configuration nobody is running.

One thing that must never restart: the gimbal

If you were slewing when contact went, the gimbal stopped on its own about half a second later, because the rate frames expired and nothing was telling it to move — that is the property the bench run measured. When the link returns, it must not pick up where it left off. The commanded rate comes back at zero and the dial comes back centred, every time, so aiming is something you restart by touching the control rather than something that resumes because a radio did. Resuming a picture is honouring an instruction that still stands; resuming motion would be Yonder deciding to move an aircraft's camera on the strength of a reconnection, and rule 4 says that is not ours to decide.

Two soft keys earn their place here and nowhere else. Re-probe asks this camera again what it can do — the same question R‑CAM‑12 asks of the board, aimed at one device, for when you have changed a lens or the camera has had a firmware update. Receive line puts the exact command for receiving this stream on screen, generated from the settings above, so nobody has to read a document to configure a ground station by hand. Change the codec and that line changes with it.

3 · The same page on a tablet

R‑UI‑04 wants this usable in the field, and nothing in this conversation has been checked against a narrow screen. These are the real widths — 1024 px landscape and 768 px portrait — and the deck reflows by its own width rather than the window's, so it behaves the same embedded in the Cockpit later as it does here. Nothing is rearranged and nothing is hidden; the columns wrap and the rail wraps with them.
