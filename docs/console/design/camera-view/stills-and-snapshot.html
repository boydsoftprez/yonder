Stills, and the snapshot key

The same mechanism does three jobs: it draws the other cameras in the strip, it is what a browser gets when WebRTC will not establish, and on a link that cannot carry video it is a mode an operator would choose. So it is not a failure state — it is the picture's second setting.

Off is not the same as the link being down, and it must not look like it. It is grey rather than red, it says not requested rather than no contact, and the strip beside it says the ground station is still being fed — because turning off your own view changes nothing about what the aircraft is sending anyone else. That distinction is the whole reason Off earns a setting rather than being something you achieve by closing the tab.

A picture beats an error. Twelve seconds without a media path and it drops to stills by itself rather than showing a dialog — you still see the aircraft, at 12 kb/s, while it keeps trying. The badge says why it is on stills rather than only that it is, because "did not connect" and "you chose this" want different reactions from you. Try live again is on the rail, not a link in a message.

The reason line matters more than it looks: a browser blocked by a corporate network, a carrier eating UDP and a camera that has stopped producing frames all present as no picture, and only one of them is worth walking outside for.

Falling back to a cheaper picture is not a decision about the aircraft — nothing is commanded, nothing changes on the board — so rule 4 has no opinion here and the default should just be the useful one.

Snapshot

Same rule as recording: it happens wherever this camera can do it, and the page says where. What differs is that a board‑side snapshot is a file Yonder holds, so it can be looked at and taken away.

Two honest differences, both visible on the page. The camera's own photo is at full sensor resolution and Yonder never touches it — so there is no View, no Download and no Delete, and saying that plainly beats letting someone look for a gallery that cannot exist. The board's frame grab is whatever the pipeline is producing, which is lower, but it is a file on a card Yonder owns, so those three keys are real. The white flash is a deliberate confirmation that something happened at the moment you pressed — R‑UI‑05 wants proof of effect, and on a link with a third of a second of lag a button that dims for 300 ms is not proof of anything.
